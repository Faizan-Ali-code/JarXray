====================================================================
 JARXRAY - START HERE
====================================================================
This folder holds only the tool itself, well under 1 MB. The large parts
are downloaded on each machine the first time the tool is set up there:

    what                              size    put there by
    .venv\  (Python packages)        ~60 MB   scripts\setup_venv.bat
    tools\dependency-check\          ~33 MB   scripts\setup_dependency_check.bat
    tools\dependency-check\data\    ~250 MB   the first scan
      (the NVD vulnerability database)

    A. First use on a new machine, or after a git clone
    B. Putting the tool on GitHub, and pushing changes later

For everyday use (lib folders, the daily schedule, AI, email) and for
error messages, see README.txt.


A. FIRST USE ON A NEW MACHINE, OR AFTER A GIT CLONE
--------------------------------------------------------------------
You need Java 11 or newer, an NVD API key (free, from
https://nvd.nist.gov/developers/request-an-api-key) and internet access
to github.com, pypi.org and nvd.nist.gov.

1. Check Java: "java -version" in a command prompt must print 11 or
   higher. dependency-check needs it.

2. ONLY if this folder has no run_dependency_check.exe (the Python
   version, e.g. a QA/PROD server or a git clone): install Python 3.9 or
   newer, then double-click
       scripts\setup_venv.bat
   It creates .venv and installs the tool's packages into it. Nothing is
   installed into the system Python.

3. Double-click
       scripts\setup_dependency_check.bat
   It downloads OWASP dependency-check 12.2.2 (about 29 MB) into
   tools\dependency-check and checks it against the SHA-256 published for
   that release.
   - No internet on this machine? Download the zip it names in a browser
     and run:  scripts\setup_dependency_check.bat --zip "<the zip>"
   - dependency-check already installed elsewhere? Skip this step and set
     DEPCHECK_BIN_FOLDER (step 5) to its bin folder.

4. Double-click run_dependency_check.bat once. It creates
   config\config.txt from config\config.template.txt and stops.
   (Skip this step if config\config.txt is already there, e.g. because
   the folder was copied with its settings.)

5. Open config\config.txt in Notepad and fill in:
       NVD_API_KEY           your NVD API key
       APP_FOLDERS           the lib folder(s) to scan, e.g.
                             APP_FOLDERS=D:\QA\OrderService\lib
       INTERNAL_PACKAGES     your own package prefix(es), e.g.
                             com.example - those jars are not scanned
       DEPCHECK_BIN_FOLDER   only if dependency-check is NOT in
                             tools\dependency-check: its bin folder
   Save. Every setting is explained next to it in that file, and
   README.txt explains the lib folders and the schedule in detail.

6. Double-click run_dependency_check.bat for the first scan.
   THE FIRST SCAN TAKES LONG: dependency-check downloads the NVD database
   (about 250 MB) and builds it before it scans anything. Expect one to
   two hours or more (a measured run took 135 minutes, 18 of them for the
   scan itself). Keep the window open and the PC awake until it ends.
   After that, each scan only fetches the day's changes and takes
   minutes.
   To skip the wait: copy the tools\dependency-check\data folder of
   another install into tools\dependency-check\ before this step.

7. Optional, a daily scan at a fixed time: in config\config.txt set
       SCHEDULE_ENABLED=yes
       SCHEDULE_TIME=22:00
   then double-click setup_schedule.bat once.


B. PUTTING THE TOOL ON GITHUB
--------------------------------------------------------------------
This is for the Python version (the folder that has a .gitignore file).
The portable .exe package is not meant for git.

For your own fork, a PRIVATE repository is the safer choice once your
config holds real lib paths and package names.

What git leaves out
    The .gitignore file in this folder keeps out everything a machine
    builds or owns, so a commit is about 30 files, under 1 MB:

        .venv\, tools\                     rebuilt by part A
        config\config.txt                  your settings (keys belong in environment variables)
        config\app_list.txt,               this machine's own settings
          config\prompt_template.txt,
          config\ai_recommendation_cache.json
        apps\ (except its README),         this machine's input and output
          reports\, work\

First push (git installed, a new empty repository created on GitHub)
    Open a command prompt in this folder and run:

        git init
        git add .
        git status

    git add may print "LF will be replaced by CRLF" for many files. That
    is only a note about line endings; ignore it.

    STOP and read the list git status prints: config\config.txt must
    NOT be in it. Then:

        git commit -m "JarXray"
        git branch -M main
        git remote add origin https://github.com/<org>/<repo>.git
        git push -u origin main

Pushing later changes (for example after this folder was updated to a
new version)

        git status
        git add .
        git commit -m "<what changed>"
        git push

Using it on another machine

        git clone https://github.com/<org>/<repo>.git

    then follow part A in the new folder.

If something goes wrong
    git status lists config\config.txt
        -> The .gitignore file is missing from this folder. Do not commit.
           Put .gitignore back (it comes with the tool) and run git status
           again.
    config\config.txt was pushed anyway
        -> Treat the keys in it as leaked: create new NVD / OpenAI keys
           (and change the SMTP password) right away. Removing the file
           in a new commit does not remove it from the history.
    git commit says "Please tell me who you are"
        -> git config --global user.name "Your Name"
           git config --global user.email "you@example.com"
    git commit is stopped by a "pre-commit" hook (e.g. a static analyzer)
        -> That check comes from this machine's git settings, not from the
           tool. Ask whoever maintains it (IT). Do not skip it with
           --no-verify unless they agree.
    git push asks for a password
        -> GitHub does not take your account password here. Sign in when
           Git Credential Manager asks, or use a personal access token.
    git push fails with "file is larger than 100 MB"
        -> Something from tools\ or .venv\ got into a commit (.gitignore
           was missing). If nothing was pushed yet, the simplest fix is to
           delete the hidden .git folder (rmdir /s /q .git) and start
           again from git init, with .gitignore in place.
